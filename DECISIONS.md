# Decisions

Append-only log of choices SPEC.md doesn't settle, and of any deviation from it. Format: `D<n> — <date> — <decision>. Why: <reason>.`

## Pre-decided (from SPEC §22)
- **D1:** Compositions are HTML + GSAP, rendered by our own renderer. No Remotion; no dependency on HyperFrames.
  - Why: Remotion's license would charge our users' 4+ person teams and restricts rendering services. HyperFrames is owned by a competitor and still pre-1.0. Agents write plain HTML best.
- **D2:** pnpm + Node is the reference runtime; bunx is supported.
  - Why: Playwright and `npx` are the most common path.
- **D3:** Config lives in `.demovie/config.json` (JSON + JSON Schema).
  - Why: it works without installing the package, and agents can edit it safely.
- **D4:** Use the system ffmpeg; don't bundle it.
  - Why: bundled builds carry GPL codecs and are large.
- **D5:** Agent integration is skill-first. `make` is only a convenience launcher.
  - Why: skills work across agents, and vendor CLIs and terms change quickly.
- **D6:** No telemetry.
  - Why: trust.
- **D7:** MIT license.
  - Why: adoption.
- **D8:** v1 captures are screenshots + element maps.
  - Why: simple and reliable; DOM snapshots come later.

## Build-time decisions

- **D9** — 2026-10-01 — Pin `playwright-core` to 1.60.0. Why: its Chromium build (r1223, Chrome 148) is already in the local Playwright cache, so building and testing never downloads browsers outside the repo; 1.61–1.63 need r1228–r1243. Users install the matching Chromium with `demovie doctor --fix`.
- **D10** — 2026-10-01 — TypeScript 5.9.3, not 6.x/7.x. Why: SPEC §5.2 says TypeScript 5.x; 5.9 is the last 5.x.
- **D11** — 2026-10-01 — vitest 4.1 (not 5.0). Why: 5.0 is days old; 4.1 is mature and supports Node 20.
- **D12** — 2026-10-01 — commander 14 and execa 9 (not commander 15 / execa 10). Why: the latest majors require Node ≥ 22; demovie supports Node ≥ 20.19 (SPEC §5.2).
- **D13** — 2026-10-01 — Exclude `sharp` via `pnpm.ignoredOptionalDependencies`. Why: Next.js pulls it optionally and its libvips binary is LGPL-3.0; the Harborly fixture doesn't use `next/image` optimization, and no GPL-family code may appear anywhere in the tree.
- **D14** — 2026-10-01 — Verified Next.js 16.3.8 (docs shipped in `node_modules/next/dist/docs`): `proxy.ts` at the project root or `src/`, exporting `proxy` (or default) plus `config.matcher`; it runs on the Node.js runtime by default and rejects a `runtime` option; `middleware.ts` is deprecated but still read. demovie parses both files.
- **D15** — 2026-10-01 — Internal packages export TypeScript source (`exports: ./src/index.ts`); only `demovie` (tsdown) and `@demovie/runtime` (esbuild) are built. tsdown's `deps.onlyBundle: [/^@demovie\//]` fails the build if any third-party package would be bundled; every third-party dependency stays a declared npm dependency of `demovie`. Why: one build step, accurate license accounting, fast tests.
- **D16** — 2026-10-01 — While milestones are pending, `pnpm verify` ends with `VERIFY OK (<passed> checks, <k> pending)`; with nothing pending it prints exactly `VERIFY OK (<n> checks)`. A check is pending only while the files it verifies don't exist yet. Why: SPEC §18 allows `pending` during the build but not at the end, and the final line must stay unambiguous.
- **D17** — 2026-10-01 — Tests, verify and smoke tests write temporary files only under `<repo>/.tmp/` (gitignored), never the OS temp dir. Why: AGENTS.md forbids modifying files outside the repository.
- **D18** — 2026-10-01 — Harborly loads Geist through the `geist` npm package (which wraps `next/font/local`), not `next/font/google`. Why: no network at build/dev time ("no external services"); demovie's extractor maps `geist/font/sans|mono` to "Geist"/"Geist Mono" and copies the OFL woff2 files.
- **D19** — 2026-10-01 — Harborly's settings page shows `maya.chen@acme-rockets.example` and `sk_live_…` as the values redaction must catch. Why: the config allow-lists `*@harborly.demo` (the fictional demo domain, as in SPEC §6.1), so the redaction target must be an email outside that domain.
- **D20** — 2026-10-01 — Harborly's `next.config.ts` sets `agentRules: false`. Why: Next 16.3 `next dev` writes AGENTS.md/CLAUDE.md into the app folder when it detects an AI agent (verified in `next/dist/server/lib/generate-agent-files.js`); a fixture must not grow files when tests run it.
- **D21** — 2026-10-01 — Harborly's app URL is `http://localhost:3000`, never `127.0.0.1`. Why: Next 16 `next dev` blocks `/_next/hmr` for the 127.0.0.1 origin, so pages browsed there never hydrate (no charts, no client state). demovie's detection already defaults to `localhost`.
- **D22** — 2026-10-01 — Harborly computes server-side "now" (KPIs, overdue states, timestamps of projects created by flows) from `db.meta.referenceNow` (2026-09-15T10:30Z in seeded data); relative times ("2h ago") are computed client-side, so `demo.now` controls them. Why: captures must not drift with the real clock.
- **D23** — 2026-10-01 — Harborly's primary `oklch(0.546 0.245 262.881)` normalizes to `#155dfc` (Tailwind v4 blue-600), not `#2563eb` (Tailwind v3 blue-600, a different oklch value). Why: verified by the converter's unit tests against Tailwind v4's published hex values.
- **D24** — 2026-10-01 — Static analysis of JS/TS (next.config, tailwind.config, layout metadata, proxy matcher, seed files, import graphs) uses esbuild to strip types/JSX (with `verbatimModuleSyntax` so value imports survive) plus `acorn` (MIT) for the AST. Nothing from the user's project is ever executed.
- **D25** — 2026-10-01 — `init --url <url>` selects generic mode even inside a Next.js project, as SPEC §8.1 says ("generic mode when --url is given"); `--framework nextjs` overrides it.
- **D26** — 2026-10-01 — `glossary.md` format: an H1, a key list (`**Product name:**`, `**Tagline:**`, `**CTA URL:**`), then `## Features` (`- Term — source`), `## UI labels`, `## Entities`, `## People`, `## Avoid`, `## Discovered`. Discovered items count as `uiLabels` in glossary.json (they are real captured UI text); capture and extract only ever append to Discovered.
- **D27** — 2026-10-01 — Pages Router discovery also skips `404`/`500` error pages, besides `_app`, `_document`, `_error` and `api/**`. Why: they aren't product screens.
- **D28** — 2026-10-01 — Route protection: when `proxy.ts`/`middleware.ts` references auth (login/session/redirect), a route is protected iff its matcher matches; otherwise folder names are hints (`(dashboard)`, `(app)`, `(auth)`, `app/`, `dashboard/` …). Login/sign-up pages are never protected. When the app is reachable, an unauthenticated probe confirms: a redirect to login (or 401/403) means protected.
- **D29** — 2026-10-01 — Runtime primary color: if any filled button (contrast ≥ 1.5 against the page background) matches the static `--primary`, the token is "runtime-confirmed"; otherwise the largest filled button's color wins, and the static value is kept in provenance. Why: SPEC §8.3 says runtime wins for rendered colors, and dark CTA buttons on many sites would otherwise override a real primary.
- **D30** — 2026-10-01 — Code that runs inside pages (`page.evaluate`) is written as plain JS strings. Why: tsx/esbuild `keepNames` helpers (`__name`) leak into serialized functions and crash in the browser.
- **D31** — 2026-10-01 — Brand font files are stored as `brand/fonts/<family-slug>-<weight|variable>.<ext>` (e.g. `geist-variable.woff2`). Why: `brand.json` lists files without per-file weights; the runtime derives `font-weight` (a range for variable fonts) from the name.
- **D32** — 2026-10-01 — Capture freshness: a state is stale when the config hash or a hashed source file (page + layout chain; flow file) changed, or its screen.png is missing. The git HEAD is recorded for provenance and `--changed --since`, but a moved HEAD alone doesn't make every capture stale. Why: otherwise every unrelated commit would invalidate all captures and `--changed` would be useless.
- **D33** — 2026-10-01 — The tarball smoke test (`pnpm verify` check 14) installs the packed `demovie` tarball with `npm install` into `.tmp/smoke/` (third-party dependencies come from the npm registry, using the user-level npm cache), then runs `npx --no-install demovie --version`, `doctor --json` and `init --yes` on a Harborly copy, and repeats `--version`/`doctor` with `bun add` + `bunx` when bun is installed. Why: closest local equivalent of `npx demovie` without publishing.
- **D34** — 2026-10-01 — Capture runs the demo seed at the start of every `capture`/`up` (also when reusing a running app), and flows run after all route states, one at a time. Why: flows change demo data (create-project adds `prj_q4-launch`), and re-seeding first keeps flow URLs, captured text and element ids identical across runs.
- **D35** — 2026-10-01 — `capture --route …` without `--flow` captures only those routes; flows run when named with `--flow`, or when the capture isn't narrowed. A flow runs at its declared `viewport` unless both `--flow` and `--viewport` are given. Why: `capture --viewport mobile --route / --route /app/projects` (SPEC §20 M2) must not replay a desktop-only flow at phone size.
- **D36** — 2026-10-01 — `capture.routes.params` in config.json wins over params found by crawling (routes.json). Why: SPEC §8.2 orders the sources config → crawl → `needsParams`.
- **D37** — 2026-10-01 — Before each flow capture the mouse is parked at (0,0) unless the previous step was `hover`, and Chromium is launched with `--lang=<demo.locale>`. Why: Playwright leaves the mouse over the last clicked element (unwanted hover styles), and date inputs follow the browser UI language, not the context locale.
- **D38** — 2026-10-01 — `auth record` (headed browser, manual login) is exercised manually only; automated tests cover `form`, `script`, and `storageState` from a saved state (SPEC §18 lists exactly these). Why: a headed login needs a person.
- **D39** — 2026-10-01 — Integration tests capture into copies of Harborly (`.tmp/it-*`) whose seed command reseeds the running original (`pnpm --dir examples/harborly demo:seed`). Why: the dev server serves `examples/harborly`, and tests must never rewrite its committed `.demovie/` files.
- **D40** — 2026-10-01 — Harborly's committed `.demovie/` is the output of `demovie init --yes` + `extract` + `capture` (glossary Discovered labels and route titles included), plus three hand edits a user would make: `demo.now` matching the seed's reference time, `capture.routes.params` (`prj_launch`) and `waitFor` selectors for chart pages, and an `## Avoid` list (tasks, tickets, sprints). A second capture leaves these files byte-identical. The copied Geist woff2 files ship with their OFL license text.
- **D41** — 2026-10-01 — `qa`, `stills`, `render`, `preview` and `audio *` accept either a slug (`.demovie/videos/<slug>`) or a path to a video folder. Why: the reference compositions live in `examples/compositions/` (SPEC §16.2) but render against Harborly's `.demovie/` (`--cwd examples/harborly`).
- **D42** — 2026-10-01 — Frame format: PNG for `final`, JPEG q92 for `draft` (SPEC §11.2). Benchmark (clean-launch, 1080p, one worker, seek + CDP capture): PNG 79.7 ms/frame (278 KB), JPEG 35.8 ms/frame (138 KB). Why: JPEG is 2.2× faster but adds a second lossy generation (JPEG, then H.264) that softens small UI text; drafts don't care, finals do.
- **D43** — 2026-10-01 — Render Chromium flags (SPEC §11.1, documented in `packages/render/src/session.ts`): sRGB color profile, no LCD text, no font hinting/subpixel positioning, software raster (`--disable-gpu`), no Skia runtime opts, no partial raster or checker-imaging, all compositor stages before draw, no background throttling, hidden scrollbars, muted audio. Verified: the same frame rendered twice and in shuffled seek orders is byte-identical.
- **D44** — 2026-10-01 — The renderer polls `__DEMOVIE__.ready` from Node instead of `page.waitForFunction`. Why: in-page polling uses the page's timers, which the virtual clock turns into no-ops after `v.ready()` (SPEC §10.1); a poll scheduled just before ready never fires, so parallel workers hung intermittently.
- **D45** — 2026-10-01 — The runtime never uses synchronous requests: the render/preview server exposes `/__demovie/captures.json` (meta + element map of every capture) and `createVideo()` preloads it plus the brand's SVG logos. Why: synchronous XHR stalls under Playwright request interception (the render sandbox), and `screen()`/`logo()` must stay synchronous (SPEC §10.3).
- **D46** — 2026-10-01 — `logo()` inlines SVG logos into the DOM. Why: an SVG loaded as `<img>` cannot use page fonts, so a wordmark's `<text>` would fall back to a system font instead of the brand font.
- **D47** — 2026-10-01 — Output scale below 1 (drafts, stills) renders at device scale factor 1 and downscales in the CDP screenshot clip. Why: Chromium ignores a `deviceScaleFactor` below 1. Scale ≥ 1 uses the device scale factor directly (crisp 4K).
- **D48** — 2026-10-01 — Draft renders are named `<slug>-<fmt>.draft.mp4` / `poster-<fmt>.draft.png`; finals keep `<slug>-<fmt>.mp4` (SPEC §11.3). A final render sets video.json `status` to `rendered`; the render id (frame cache key) hashes video.json without `status`. Why: a draft must never overwrite a final, and marking a video rendered must not invalidate its frame cache.
- **D49** — 2026-10-01 — Encoding tags BT.709 on the frames themselves (`scale=…:out_color_matrix=bt709` + `setparams=color_primaries=bt709:color_trc=bt709:colorspace=bt709:range=tv`). Why: ffmpeg 7 takes stream color tags from frame properties; the `-color_*` output options alone left primaries/transfer `unknown`.
- **D50** — 2026-10-01 — Runtime layout semantics: shot visibility is computed per seek from each shot's window (transitions widen windows; overlapping shots stack in creation order); camera, scroll, swaps, cursor paths and highlights are pure functions of `t` evaluated per seek (not GSAP tweens), so the cursor always lands where the camera put the element. `focus(rect)` takes a Rect in stage px at the base transform (the space of `rect()`); `typeText` overlays belong to the capture shown when typing started; the browser bar shows the path of the capture on screen.
- **D51** — 2026-10-01 — The runtime fetches `audio/beats.json` and the voice manifest only when video.json declares them. Why: probing for missing files produced 404s, which QA rule DM-A02 rightly treats as errors.
- **D52** — 2026-10-01 — Golden images: `examples/compositions/clean-launch/goldens/` holds 0.5-scale stills (6 times × 2 formats) with a manifest naming the recording platform (`darwin-arm64`); the test compares with pixelmatch (threshold 0.1, ≤ 0.2 % differing pixels) on that platform and logs a skip elsewhere. `pnpm test:update-goldens` re-records them.
- **D53** — 2026-10-01 — `demovie new` starts a scaffold from a real capture when one exists: a logged-in, non-dynamic route with `data-demovie` elements, shallowest path first, focusing a tagged region covering 5–45% of the viewport. Copy defaults come from the glossary (feature term or `--about`, tagline, a CTA-like UI label, the CTA URL); templates live in `packages/skill/templates/` so agents can read them.
- **D54** — 2026-10-01 — `demovie add` keeps the original file name slugified, transcodes videos to VP9 WebM without audio (audio comes from the mix), records licensed audio in `.demovie/assets/provenance.json` (generator `user-licensed`), and refuses audio without `--licensed`.
- **D55** — 2026-10-01 — `demovie preview` binds 127.0.0.1, takes the first free port from `--port` (default 4400) upward, and opens the browser only in interactive terminals. Hot reload watches the composition, video.json, audio/, captures/, brand/ and qa.json.
- **D56** — 2026-10-01 — QA samples `inspect()` at 10 fps (plus the last frame) on a scale-1 page and grabs 0.5-scale pixels for the pixel rules; clicks are judged at their own times; DM-R01 renders 5 frames (15/35/55/75/92 % of the duration) again on a fresh page in reverse order after seeking to the end, and requires zero differing pixels. Why: geometry in stage px, pixels cheap enough for 350 samples per format (~22 s per 35 s format).
- **D57** — 2026-10-01 — Rule interpretation: a text block is visible when its mean effective opacity ≥ 0.3 and it intersects the stage; product-UI overlays (typeText, browser URL bar, cursor) are UI and exempt from text rules. Layout/size/contrast/clip/text-amount rules (T02–T05, L01, L02) only fire when the violation persists ≥ 0.2–0.3 s and outside declared transitions; L03 needs > 1 s (SPEC). Why: entrance animations and transitions legitimately pass through small, clipped or overlapping states for a few frames.
- **D58** — 2026-10-01 — DM-T04 samples the background as the per-channel median of a ring 5 px outside the text box in the frame's pixels, blends the text color by its alpha, and only judges fully opaque text. DM-R02 calls a frame blank when its most common 5-bit-quantized color covers > 98 % of it.
- **D59** — 2026-10-01 — DM-G02/G04 vocabulary: words and number tokens from glossary.json, brief.md and the element names/texts/values of the captures the video uses. A "capitalized term" is a capitalized word that doesn't start a sentence, or an acronym; numbers inside words (Q4, v2) don't count; counters are judged by their final value.
- **D60** — 2026-10-01 — qa.json rule results carry a `title`, and occurrences of persistent violations carry `until` (the last sampled time they hold) next to `t`, so the preview overlay can show violations at any time inside the span. The schema stays a superset of SPEC §12's.
- **D61** — 2026-10-01 — `bad-*` fixtures declare their intended rules in `expected-qa.json`; verify check 7 passes when every intended rule fails (other rules may fail too) and every reference composition has 0 errors in all formats. The `bad-audio` fixture ships two locally generated test tones (ffmpeg lavfi sine) with no provenance on purpose; `scripts/check-licenses.ts` exempts exactly that folder.
- **D62** — 2026-10-02 — Music structure from the storyboard: the first shot is the intro (unless it is a product shot: then 2 bars), a final logo/title/text shot is the outro and its start gets the ending hit, the first ≤ 2 bars after the intro are the build, the rest is main. The beat grid's offset puts a bar line exactly on the ending hit; the other section boundaries snap to the nearest bar. Why: SPEC §13.1 asks for storyboard sections and an ending hit on the final shot; a downbeat on the hit is what makes it land.
- **D63** — 2026-10-02 — Music defaults: mood by style (clean→uplifting, bold→energetic, soft→calm, editorial→minimal, terminal→tech), BPM from the storyboard frontmatter else the mood's default, seed = the video slug, key picked from the seed in the mood's mode. `audio music` gets an extra `--key` flag (SPEC lists key as an input without a flag). Output peaks at −1 dBFS after a −1.5 dBFS look-ahead limiter; provenance license CC0-1.0.
- **D64** — 2026-10-02 — Bundled SFX: 12 deterministic DSP generators, 48 kHz stereo 16-bit WAV, each normalized to a catalog peak (−2…−6 dBFS), 1.6 MB in total, in `packages/audio/sfx` with `provenance.json` (CC0-1.0, sha256) and a README. `pnpm sfx:generate` rewrites only changed files; a unit test asserts the bundled bytes equal the generator output.
- **D65** — 2026-10-02 — `audio mix` builds the pre-mix in TypeScript (music gain, a deterministic −8 dB duck envelope computed from the VO line times with the 150 ms attack ending at the line start and a 400 ms release, a 1.0 s cosine fade-out, VO at its starts, SFX at their cues) and then runs ffmpeg's two-pass `loudnorm` in linear mode (target LRA raised to the source's so linear mode isn't refused). When the loudness gain would push true peaks over the target, the pre-mix is peak-limited 1 dB under it first. Output: 48 kHz stereo pcm_s16le with bit-exact headers. Why: SPEC fixes the duck depth/attack/release exactly; a gain envelope gives exactly that (sidechaincompress doesn't), and linear loudnorm avoids pumping. clean-launch measures −15.7 LUFS / −2.4 dBTP (mix) and −15.8 LUFS in both MP4s.
- **D66** — 2026-10-02 — Provenance writes are idempotent: an entry whose generator, license and details (which include the file's sha256) are unchanged keeps its `createdAt`, and entries are written in a fixed key order. With deterministic synth/mix output, regenerating audio leaves every file byte-identical.
- **D67** — 2026-10-02 — Reference compositions don't commit generated WAVs (`examples/compositions/*/audio/*.wav` is gitignored except the bad-audio fixture); `pnpm verify` regenerates music and mix before QA and rendering. Their beats.json and provenance.json are committed. Biome ignores generated audio JSON (`beats.json`, `voice.json`, `provenance.json`), which the CLI writes with JSON.stringify formatting.
- **D68** — 2026-10-02 — ElevenLabs TTS (checked against the API reference 2026-10-02): `POST /v1/text-to-speech/{voice}/with-timestamps?output_format=mp3_44100_128`, `xi-api-key`, body `{ text, model_id }`; default model eleven_multilingual_v2; default voice `21m00Tcm4TlvDq8ikWAM` (the reference's example voice; pass --voice or set audio.voice.voiceId for your own). Words come from `alignment` (the original characters), falling back to `normalized_alignment`; duration from ffprobe, else the last character's end. Price table: multilingual v2 $0.08 / 1K chars, flash/turbo v2.5 $0.04 / 1K; unknown models print "price unknown".
- **D69** — 2026-10-02 — OpenAI TTS: `POST /v1/audio/speech` with `response_format: "wav"`, so duration and the spoken span (first/last sample above −40 dBFS) are read without ffprobe; words are spread over that span in proportion to their length + 1 and marked `estimated: true`. Defaults: gpt-4o-mini-tts, voice alloy (works with every TTS model). Cost: tts-1 $15 / 1M chars, tts-1-hd $30 / 1M chars, gpt-4o-mini-tts ≈ $0.015 per minute at ~900 characters per minute.
- **D70** — 2026-10-02 — Voice cache key = sha256([provider, model, voice, text]) → `.demovie/.cache/voice/<key>.<ext>` + `<key>.json` (duration, words). Only uncached lines are estimated and need confirmation (`--yes`, an interactive confirm, otherwise exit 2 with `fix: re-run with --yes`). Keys are read from env or `.demovie/.env`, registered with the logger's secret masking, and never written to manifests, provenance or errors.
- **D71** — 2026-10-02 — The "user-provided script resource" is `audio voice --script <file>`: one VO line per line, optionally prefixed `[12.5]` or `12.5 |` for its start; untimed lines start 0.4 s after the previous line ends (the first at 0.5 s). Storyboard lines get ids `vo-<shot #>` and start with their shot; files are `audio/<id>.mp3|wav`; stale `vo-*` files and their provenance are removed on re-runs.
- **D72** — 2026-10-02 — ElevenLabs Music (API reference checked 2026-10-02): `POST /v1/music?output_format=mp3_44100_128` with `{ prompt, music_length_ms, force_instrumental: true }`; no `model_id` (API default) and no `seed` (the API rejects it together with a prompt). The prompt is built from mood, BPM, key, duration, sections and the ending hit; cost ≈ $0.15 per minute, confirmed like voice. Its beat grid, and that of `--provider file` (an extra choice for the config's "file" provider: video.json audio.music.src → a track in .demovie/assets imported with `add --licensed`), uses the requested BPM and an energy-flux onset phase search for the offset. DM-A04 checks such tracks against `.demovie/assets/provenance.json`.
- **D73** — 2026-10-02 — Caption cues are shared: ≤ 7 words and ≤ 42 characters, breaking after sentence punctuation, held up to 0.6 s after the last word (never into the next cue). `packages/runtime/src/cues.ts` (burn-in) mirrors `packages/audio/src/captions.ts` (VTT/SRT) and a unit test checks they agree; render's sidecars now use the audio module.
- **D74** — 2026-10-02 — renderId hashes video.json without soundtrack-only settings (SFX cues, gains, loudness target, music src); the beats and voice manifests stay in the hash. Why: adding SFX must not re-render 2 × 1050 identical frames. Deviation from the letter of SPEC §11.2 ("video.json"), not its intent.
- **D75** — 2026-10-02 — ffmpeg/ffprobe lookup and `measureLoudness` moved to @demovie/audio (render re-exports them). verify's test checks fail on any skipped test whose name doesn't contain "live" (GOAL: only live paid-API tests may skip), and check 8 asserts the rendered loudness is within the video's target ± 1 LU.
- **D76** — 2026-10-02 — Skill install locations (verified in the vendors' docs 2026-10-01): project-level `.claude/skills/demovie` (Claude Code; it does not read `.agents/skills`) and `.agents/skills/demovie` (Codex reads repo `.agents/skills`; Cursor reads `.agents/skills`, `.cursor/skills` and `.claude/skills`). `skill install` defaults to both; `--global` (explicit only) writes `~/.claude/skills`, `~/.agents/skills` or `~/.cursor/skills`. The skill carries `metadata.version` (Agent Skills frontmatter allows a string map), stamped from the CLI version by the skill build; `status` warns when an installed copy is older.
- **D77** — 2026-10-02 — Plugin and marketplace formats checked against the Claude Code plugin docs and with `claude plugin validate --strict` (claude 2.1.247): `plugins/demovie/.claude-plugin/plugin.json` (name, version, description, author, license, keywords), `plugins/demovie/.mcp.json` registering `npx -y demovie mcp`, `plugins/demovie/skills/demovie/` (a generated copy of `packages/skill/demovie`, committed so the marketplace installs from git), and `.claude-plugin/marketplace.json` with source `./plugins/demovie`. zod schemas for all of these live in `packages/core/src/schemas/plugin.ts`; they are internal formats, so no JSON Schema is published for them.
- **D78** — 2026-10-02 — `npx skills add <owner>/demovie` compatibility relies on the skills CLI's documented discovery (it follows local `./` sources in `.claude-plugin/marketplace.json` to `<source>/skills/<name>/SKILL.md`). verify emulates that discovery instead of running `npx skills add`, which would download the CLI and install outside the repository.
- **D79** — 2026-10-02 — The skill build (`pnpm skill:build`, also the @demovie/skill package build) generates `references/runtime-api.md` from the runtime's exports with the TypeScript compiler API (signatures, interfaces, doc comments) plus a hand-written example per symbol, and `references/qa-rules.md` from the QA rules; skill lint fails when either is stale, when an export is undocumented, when a link doesn't resolve or SKILL.md exceeds 400 lines.
