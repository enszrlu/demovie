# The demovie website

The site published to GitHub Pages: a landing page with interactive demos, a gallery of every example video, and the
docs. It is plain HTML, CSS and JavaScript, generated by a small TypeScript build.

```bash
pnpm site:dev      # build, serve on http://localhost:4321/demovie/ and rebuild on changes
pnpm site:build    # build once into site/dist (fails on broken internal links or anchors)
pnpm site:media    # regenerate site/media and site/data from local renders and captures
```

## What comes from where

| Part of the site | Source |
|---|---|
| Docs pages and their sidebar | `docs/**/*.md`, grouped as in `docs/README.md` |
| FAQ, comparison table, QA rules | `docs/faq.md`, `docs/comparison.md`, `docs/qa-rules.md` |
| Gallery facts, briefs and shot lists | each video's `video.json`, `brief.md` and `storyboard.md` |
| Videos, posters, captures, social card | `site/media/`, made by `pnpm site:media` |
| Element map, flow, QA findings, CLI output | `site/data/`, made by `pnpm site:media` |
| Page templates, styles and scripts | `site/src/` |

Edit the docs in `docs/`, never in the site: the build reads them every time.

## Regenerating the media

`pnpm site:media` reads renders and captures that are gitignored, so make them first:

```bash
pnpm build
node packages/cli/dist/index.js --cwd examples/harborly capture
node packages/cli/dist/index.js --cwd examples/harborly render launch
node packages/cli/dist/index.js --cwd examples/harborly render changelog
node packages/cli/dist/index.js --cwd examples/harborly render projects-board-teaser
node packages/cli/dist/index.js --cwd examples/harborly render ../baseline-one-prompt --format 16:9
for s in clean bold soft editorial terminal; do node packages/cli/dist/index.js --cwd examples/harborly render ../compositions/$s-launch; done
pnpm site:media                        # or one step: --only videos,hero,captures,qa,share,terminal,og
```

Commit what changed in `site/media` and `site/data`. Keep the files small: videos are web copies (1280 px wide for
16:9) and posters are WebP.

## Publishing

`.github/workflows/pages.yml` builds and deploys on pushes to `main` that touch the site, the docs or the examples. In
the repository settings, set **Pages → Build and deployment → Source** to **GitHub Actions**. A custom domain works
without code changes: the workflow passes the published URL to the build as `SITE_URL`.
